# Firewall Lab 7

## Розробка програмного брандмауера

Навчальний програмний брандмауер на Python,
розроблений на основі шаблону викладача.

## Можливості

- Фільтрація TCP та UDP за IPv4/CIDR, портами,
  протоколами та логічними напрямками IN/OUT.
- Політика Default Deny.
- Пріоритетна обробка правил First Match.
- Додавання, редагування, активація, деактивація
  та видалення правил без перезапуску.
- Гаряче оновлення конфігурації.
- Атомарне збереження правил.
- Виявлення дублікатів, конфліктів,
  перекриття та затінення правил.
- Admin REST API з Bearer-токеном.
- Консольний інтерфейс адміністрування.
- JSONL-журналювання, ротація, пошук,
  статистика, виявлення аномалій та CSV-експорт.
- Паралельна обробка TCP/UDP-трафіку.

## Середовище

- Kali Linux Rolling 2026.3
- Python 3.14.7
- Oracle VirtualBox
- Стандартна бібліотека Python
- tcpdump та Wireshark для аналізу трафіку

## Архітектура

Client -> Firewall -> Target service

| Direction | Protocol | Proxy | Target |
|-----------|----------|-------|--------|
| IN | TCP | 8080 | 8000 |
| IN | UDP | 5353 | 9000 |
| OUT | TCP | 8082 | 8000 |
| OUT | UDP | 5354 | 9000 |

Усі сервіси працюють на loopback.
Admin API: 127.0.0.1:8081.

## Підготовка

Виконувати з кореневого каталогу проєкту.

```bash
python3 -m venv .venv
source .venv/bin/activate
python scripts/init_config.py
```

Ініціалізатор створює локальну конфігурацію
та випадковий адміністративний токен.
Наявні файли не перезаписуються.

## Запуск

У трьох окремих терміналах:

```bash
python3 scripts/tcp_server.py
```

```bash
python3 scripts/udp_server.py
```

```bash
python3 firewall.py
```

Права root для брандмауера не потрібні.

## Керування

```bash
python3 firewall_cli.py health
python3 firewall_cli.py rules
python3 firewall_cli.py conflicts
python3 firewall_cli.py stats
```

Приклад дозволяючого правила:

```bash
python3 firewall_cli.py add '{"action":"ALLOW","proto":"TCP","direction":"IN","dst_port":8000,"priority":20}'
```

Редагування, деактивація та видалення
(замість 1 вказати фактичний ID правила):

```bash
python3 firewall_cli.py patch 1 '{"enabled":false}'
python3 firewall_cli.py patch 1 '{"enabled":true}'
python3 firewall_cli.py delete 1
python3 firewall_cli.py reload
```

## Структура правила

| Поле | Призначення |
|------|-------------|
| id | Ідентифікатор |
| action | ALLOW або DENY |
| src_ip_cidr | IPv4/CIDR джерела |
| dst_ip_cidr | IPv4/CIDR призначення |
| src_port | Порт джерела |
| dst_port | Порт призначення |
| proto | TCP, UDP або ANY |
| direction | IN, OUT або ANY |
| priority | Пріоритет |
| enabled | Активність правила |

Порт 0 означає будь-який порт.
Менше значення priority має вищий пріоритет.
За відсутності відповідного правила діє DENY.

## Конфлікти

- DUPLICATE: однакова область та дія,
  зміна відхиляється.
- CONFLICT: суперечливі дії з однаковим
  пріоритетом, зміна відхиляється.
- OVERLAP: перетин областей фільтрації,
  рішення визначається пріоритетом.
- SHADOWING: правило повністю перекрито
  попереднім правилом.

Критичні конфлікти повертають HTTP 409.
Попередження не блокують коректну зміну.
Некоректні параметри повертають HTTP 400.

## Журналювання

Журнал logs/events.jsonl містить UTC-час,
IP-адреси, порти, протокол, напрямок,
рішення, причину, ID правила, версію правил
та ідентифікатор запуску.

Приклади аналізу:

```bash
python3 analyze_logs.py
python3 analyze_logs.py --action DENY --show
python3 analyze_logs.py --proto UDP
python3 analyze_logs.py --src 127.0.0.3/32
python3 analyze_logs.py --threshold 5 --window 60
python3 analyze_logs.py --csv outputs/events.csv
```

## Обмеження

Це навчальний user-space proxy firewall,
а не системний фільтр IP-пакетів.

Контролюється лише трафік, який проходить
через налаштовані проксі-маршрути.

IN та OUT є логічними напрямками.
TCP фільтрується на початку з'єднання,
UDP — для кожної отриманої датаграми.

Нові правила не розривають уже дозволені
TCP-з'єднання. Версія правил починається
з 1 після кожного запуску.

Admin API призначений лише для локального
керування. Аналіз аномалій формує сповіщення,
але не виконує автоматичного блокування.

Підтримка IPv6 та промислове навантажувальне
тестування не входять до меж реалізації.
